# MVP 설계(MVP Planning) 학습 가이드

이 문서는 제한된 실습 기간 내에 서비스의 핵심 가치를 성공적으로 실증하기 위한 최소 기능 버전(MVP) 정의 기준과 작성법, 구체적 예시입니다.

## 1. MVP(Minimum Viable Product) 판정 기준
MVP는 단순히 기능을 줄이는 것이 아니라, 사용자가 실제로 작동을 확인하여 '서비스의 핵심 가치'를 검증할 수 있어야 합니다.

* **MVP 판정 통과 조건**:
  - 사용자가 직접 로컬에서 실행하고 입력을 넣을 수 있음.
  - 입력을 넣으면 AI 처리 및 결과가 화면에 가시적으로 표시됨.
  - 보안 및 로그인, 결제 등 비즈니스 부가 기능 없이도 해결하고자 했던 핵심 가치가 달성됨.
* **MVP 판정 탈락**:
  - 화면만 있고 실제 AI 백엔드가 돌지 않는 목업(Mockup).
  - API는 도는데 사용자가 테스트할 수 있는 프론트나 수동 실행 수단이 없음.

---

## 2. MVP 포함/제외 기능 판별 가이드

| 기능 | MVP 포함 여부 | 이유 |
| --- | --- | --- |
| 회의록 텍스트 입력 | 포함 | 사용자의 핵심 데이터를 받는 출발점입니다. |
| AI 요약 생성 | 포함 | 서비스의 핵심 가치(안건 요약)를 실현합니다. |
| 요약 결과 표시 | 포함 | 사용자가 결과를 보아야 가치가 완결됩니다. |
| 사용자 로그인 | 제외 | 첫 버전에서는 개인화 없이 전역 실행만으로도 가치 증명이 충분합니다. |
| PDF 다운로드 | 제외 | 화면에서 눈으로 확인이 가능하므로 다운로드 유틸은 우선순위가 낮습니다. |

## 3. 좋은 완료 기준(Definition of Done) 예제
* **좋은 예시**:
  "사용자가 회의록 텍스트를 입력하면, 서비스가 핵심 요약과 할 일 목록을 화면에 표시한다. 빈 텍스트 입력 시 에러 안내가 출력된다. README에 기재된 명령어로 로컬 구동이 가능하다."
* **나쁜 예시**:
  "AI 회의록 요약 기능 구현 완료" (실행 확인 방법, 입력 예시, 대체 확인 방식이 없음)

## 4. MVP 계획서 작성 모범 예시 (AI 회의록 요약 서비스)

### 1. MVP 목표
- 프로젝트명: AI 회의록 요약 서비스
- MVP 한 줄 설명: 회의록 텍스트를 입력하면 핵심 요약과 할 일 목록을 보여주는 서비스
- MVP에서 검증할 핵심 가치: 긴 회의록을 빠르게 이해하고 후속 조치를 확인할 수 있는지 검증합니다.

### 2. MVP 사용자 흐름
1. 사용자가 회의록 텍스트를 입력합니다.
2. 서비스가 입력값이 비어 있는지 확인합니다.
3. AI가 핵심 안건, 결정 사항, 할 일 목록을 추출합니다.
4. 서비스가 결과를 화면에 보기 좋게 정리합니다.
5. 사용자가 요약 결과를 확인합니다.

### 3. MVP에 포함할 기능
- 회의록 텍스트 입력, AI 요약 생성, 할 일 목록 추출, 결과 화면 표시, 기본 오류 처리

### 4. MVP에서 제외할 기능
- 사용자 로그인, PDF 다운로드, 회의록 파일 업로드(텍스트 입력으로 대체)

### 5. 구현 순서
1. 텍스트 입력 폼(화면) 만들기
2. `/summarize` API 엔드포인트 만들기
3. AI 요약 처리 함수 연결
4. 결과 폼 화면에 표시
5. 예외(빈 입력) 처리
6. README 작성 및 통합 시연 검증
