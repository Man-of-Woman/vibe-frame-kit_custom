# 기능 분해(Function Breakdown) 학습 가이드

이 문서는 요구사항 정의서를 실제 구현 가능한 기능 단위로 세분화하고, API 기능과 AI Agent 기능, MVP 범위를 합리적으로 판정하기 위한 학습용 가이드와 모범 예시입니다.

## 1. 좋은 기능 분해의 기준
기능은 너무 크거나 모호하지 않게, 독립적인 입/출력을 기준으로 나눕니다.

* **나쁜 분해 예시 (너무 큼)**:
  `AI 분석 시스템 구현`
* **좋은 분해 예시**:
  - 사용자 텍스트 입력 받기
  - 입력 텍스트 길이 검증하기
  - AI 요약 요청 보내기
  - 요약 결과 화면에 표시하기
  - 오류 메시지 보여주기

---

## 2. API 기능 vs AI Agent 기능 구분
* **API 기능**: 단순 요청을 받고, 데이터를 검증하고, 데이터베이스에 쓰고, 결과를 있는 그대로 반환하는 정적/규칙 기반 처리.
* **AI Agent 기능**: AI가 여러 단계의 판단(Reasoning), 도구 사용, 반복 처리, 상태 관리 등을 능동적으로 처리해야 하는 동적 처리.

| 질문 | API 기능 | AI Agent 기능 |
| --- | --- | --- |
| 단순 요청/응답인가? | 예 | 아니오 |
| 판단이나 생성이 필요한가? | 보통 아니오 | 예 |
| 여러 단계의 AI 처리가 필요한가? | 아니오 | 예 |
| 외부 도구 선택이 필요한가? | 보통 아니오 | 예 |
| 결과 전달이 주된 역할인가? | 예 | 아니오 |

---

## 3. MVP 기능 vs 후순위 기능 판정
* **MVP 포함**: 핵심 문제 해결에 필수적이며, 없으면 서비스가 성립하지 않고, 수업 기간 내에 검증 및 테스트 가능한 핵심 단위.
* **후순위 미룸**: 개인화(로그인), 결제, UI 애니메이션, PDF 변환, 알림, 관리자 대시보드 등 비즈니스 부가 기능.

| 기능 | 분류 | 이유 |
| --- | --- | --- |
| 텍스트 입력 후 AI 요약 결과 보기 | MVP | 서비스 핵심 가치입니다. |
| 요약 결과를 PDF로 다운로드 | 후순위 | 화면 확인은 가능하므로 핵심 기획 검증엔 필수가 아닙니다. |
| 사용자 로그인 | 후순위 | 첫 버전 검증에 개인화는 필수적이지 않습니다. |
| 오류 메시지 표시 | MVP | 사용자가 실패 원인을 알고 대체할 수 있어야 합니다. |

## 4. 실제 기능 분해 예시 (AI 회의록 요약 서비스)

| 대분류 | 세부 기능 | 입력 | 처리 | 출력 | 구현 우선순위 | 관련 Agent/API |
| --- | --- | --- | --- | --- | --- | --- |
| 화면 | 회의록 텍스트 입력 | 회의록 텍스트 | 입력 폼에서 텍스트를 받음 | 입력된 텍스트 | 높음 | Frontend |
| API | 요약 요청 API | 회의록 텍스트 | 입력값 검증 후 AI 처리 요청 | 요약 결과 응답 | 높음 | API |
| AI 처리 | 핵심 내용 요약 | 회의록 텍스트 | 주요 안건과 결정 사항 추출 | 요약 문장 | 높음 | Agent |
| AI 처리 | 할 일 목록 추출 | 회의록 텍스트 | 담당자, 할 일, 기한 후보 추출 | 할 일 목록 | 높음 | Agent |
| 화면 | 결과 표시 | 요약 결과 | 요약, 결정 사항, 할 일 목록을 구분해 표시 | 결과 화면 | 높음 | Frontend |
| 오류 처리 | 빈 입력값 처리 | 빈 텍스트 | 입력값 검증 및 안내 메시지 생성 | 오류 메시지 | 높음 | API |
| 데이터 | 요약 결과 저장 | 요약 결과 | 결과를 로컬 또는 DB에 저장 | 저장된 결과 | 중간 | Database/API |
| 문서화 | README 작성 | 구현 기능 목록 | 실행 방법과 사용 예시 정리 | README.md | 중간 | Documentation |
| 부가 기능 | PDF 다운로드 | 요약 결과 | 결과를 PDF 파일로 변환 | PDF 파일 | 낮음 | API |
| 부가 기능 | 사용자 로그인 | 사용자 계정 정보 | 계정 인증 및 사용자별 결과 관리 | 로그인 상태 | 낮음 | API/Database |

### 구현 순서 권장 제안
1. 핵심 입력/출력 폼(Frontend) 구현
2. 요약 및 추출 요청 API 엔드포인트 구현
3. 핵심 요약 AI Agent 로직 연동
4. 예외 및 오류 처리 적용
5. README 문서화 및 테스트
6. 로컬 DB 저장 및 부가 기능(PDF, 로그인 등) 순차 구현
