# Function Breakdown

## 1. 목적
이 Skill의 목적은 요구사항 정의서를 실제 개발 가능한 기능 단위로 분해하는 것입니다.

## 2. 사용 상황
- 요구사항 정의서가 작성된 후 기능 목록을 정리해야 할 때
- 서비스 아이디어가 너무 커서 작은 개발 작업으로 나눠야 할 때
- API 기능과 AI Agent 기능을 구분해야 할 때

## 3. 입력 정보
- 요구사항 정의서(requirements.md)의 핵심 기능 및 처리 흐름.
- 사용자의 가용한 기술 스택 및 작업 범위 정보.

## 4. 작업 절차 및 템플릿 참조 규칙
1. 에이전트는 다음 경로의 템플릿을 동적으로 로드(`view_file`)하여 표 구조의 사양을 파악합니다: `{{INSTALL_PATH}}/templates/function-breakdown-template.md`.
2. 전체 기능을 화면, API, AI 처리, 데이터 저장, 문서화 등 대분류로 나눕니다.
3. 각 대분류를 입출력이 식별되는 세부 기능으로 나누어 우선순위와 함께 표 형식으로 채웁니다.
4. 마지막에 구현 순서 제안을 간단히 덧붙여 최종 기능 분해 명세를 출력합니다.
5. 수강생이 기능 분류 기준(API vs Agent, MVP 판정 등)이나 학습 예시를 요청할 경우, `{{INSTALL_PATH}}/study/function-breakdown-study.md` 파일을 안내 또는 참고하도록 지시하십시오.

## 5. 기능 분해 시 주의사항
- 한 번의 작업 요청으로 구현 및 검증할 수 있는 크기(입출력 명확성)로 나눕니다.
- 로그인, 결제 등 후순위 부가 기능은 MVP에서 명확히 구분하여 배제시킵니다.
- 기능 분해 목록은 이후 프로젝트 구조 생성과 API 개발의 핵심 설계 기준이 됩니다.
