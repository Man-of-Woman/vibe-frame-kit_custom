# MVP Planning

## 1. 목적
이 Skill의 목적은 전체 프로젝트 중 수업 시간 안에 먼저 구현할 최소 기능 범위(MVP)를 정하는 것입니다.

## 2. 사용 상황
- 요구사항 정의와 기능 분해가 끝난 후 첫 구현 범위를 정해야 할 때
- 수업 시간 또는 제출 기한 안에 구현 가능한 범위를 정해야 할 때
- 기능 목록이 너무 많아 무엇부터 만들어야 할지 모를 때

## 3. 입력 정보
- 요구사항 정의서(requirements.md)와 기능 분해 목록(function-breakdown.md).
- 프로젝트 기한 및 개발 인원 조건.

## 4. 작업 절차 및 템플릿 참조 규칙
1. 에이전트는 다음 경로의 템플릿을 동적으로 로드(`view_file`)하여 작성 항목을 파악합니다: `{{INSTALL_PATH}}/templates/mvp-plan-template.md`.
2. 서비스의 핵심 가치를 담은 MVP 목표와 사용자 흐름을 정의합니다.
3. 기능 분해 목록 중 MVP에 포함할 기능과 후순위로 제외할 기능을 격리하고 타당한 사유를 기재합니다.
4. 구현 순서와 테스트 확인 방법, 완료 기준(DoD)을 명시하여 최종 MVP 계획서를 생성합니다.
5. 수강생이 MVP 판정 기준이나 작성 요령, 모범 예제를 요청할 경우, `{{INSTALL_PATH}}/study/mvp-planning-study.md` 문서를 안내하거나 조회해 인용하십시오.

## 5. 에이전트 주의사항
- 한 번에 많은 기능을 구현하도록 제안하지 않고 핵심에 집중시킵니다.
- 완료 기준은 단순히 "개발 완료"가 아닌 "사용자가 입력을 넣고 확인 가능한 실행 경로 완료"로 구체적으로 정의합니다.
