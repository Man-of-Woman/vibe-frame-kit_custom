# Requirements Definition

## 1. 목적
이 Skill의 목적은 사용자의 아이디어를 AI 서비스 개발용 요구사항 정의서로 바꾸는 것입니다.

## 2. 사용 상황
- 사용자가 AI 서비스 아이디어만 가지고 있는 경우
- 프로젝트 주제는 정했지만 구체적인 기능이 정리되지 않은 경우
- 구현 전에 요구사항 정의서가 필요한 경우

## 3. 입력 정보
- 사용자가 입력할 데이터, 예상 사용자, 원하는 결과물.
- 필수로 확인해야 하는 정보: 어떤 문제를 해결하려는가? 누구를 위한 서비스인가? 사용자는 무엇을 입력하는가? 서비스는 어떤 결과를 제공하는가? 첫 번째 버전에서 반드시 필요한 기능은 무엇인가?

## 4. 작업 절차 및 템플릿 참조 규칙
1. 에이전트는 다음 경로의 템플릿을 동적으로 로드(`view_file`)하여 작성 형태를 파악합니다: `{{INSTALL_PATH}}/templates/requirements-template.md`.
2. 사용자의 서비스 목적, 대상 사용자, 입력 데이터, 핵심 기능, 처리 흐름, MVP 범위를 추출합니다.
3. 로드한 표(Table) 구조의 템플릿 서식을 100% 일치시켜 기획서를 출력합니다.
4. 사용자가 요구사항 정의 관련 개념적 예시나 좋은/나쁜 질문 예시를 요청할 경우, `{{INSTALL_PATH}}/study/requirements-study.md` 문서를 안내하거나 조회하여 인용하십시오.

## 5. 에이전트 주의사항
- 사용자의 아이디어가 모호하면 임의로 확정하지 말고 가정을 명시합니다.
- 처음부터 로그인, 결제 등 부가 기능을 MVP에 넣지 않습니다.
- 수강생이 이해하기 어려운 전문 용어를 남용하지 않습니다.
- 최종 요구사항 정의서는 이후 기능 분해와 MVP 설계에 바로 사용할 수 있는 형태로 작성합니다.
