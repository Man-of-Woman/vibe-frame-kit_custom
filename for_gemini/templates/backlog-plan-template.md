# 이터레이션 백로그 계획서 (Iteration Backlog Plan)

## 1. 이전 이터레이션 피드백 요약

* 이전 빌드 버전(예: MVP/Sprint 1) 작동 테스트 및 사용자 피드백을 통해 수집한 버그, 개선 포인트 등을 작성합니다.
  - *예시 1*: 파일 크기가 10MB를 초과할 경우 요약 시간이 60초 이상 걸리며 타임아웃 오류 발생.
  - *예시 2*: 텍스트 결과물을 파일로 직접 다운로드받고 싶다는 피드백 반영 필요.

## 2. 우선순위 기반 백로그 (MoSCoW)

* 다음 이터레이션(Sprint 2)에 반영할 요구사항들을 중요도 순으로 나누어 작성합니다.

### A. Must Have (반드시 포함해야 하는 핵심 기능 및 치명적 버그 수정)
- [ ] 대용량 텍스트 요약 처리 안정성 확보 (비동기 큐 또는 청크 분할 처리 도입)
- [ ] API 타임아웃 시간 120초로 조정 및 클라이언트 측 로딩 예외 처리 추가

### B. Should Have (포함해야 하는 주요 개선 기능)
- [ ] 요약 결과 마크다운(.md) 및 텍스트(.txt) 다운로드 기능 구현

### C. Could Have (시간 여유가 있을 때 적용할 기능)
- [ ] 처리율(Progress) 바 적용 및 로딩 애니메이션 보완

### D. Won't Have (이번 스프린트에서는 보류하고 향후 검토할 사항)
- [ ] 구글 드라이브/원드라이브 다이렉트 파일 연동 기능

## 3. 차기 이터레이션 목표 및 일정

- **스프린트 목표**: 대용량 파일의 처리 안정성을 확보하고, 사용자가 결과를 쉽게 다운로드할 수 있는 문서 내보내기 기능 통합.
- **예상 개발 일정**: YYYY-MM-DD ~ YYYY-MM-DD
- **작업자 구성**: Front: 1명 / Back: 1명
- **성공 기준**: 15MB 텍스트 파일 입력 시 타임아웃 없이 정상 작동하며, 생성된 요약 결과를 다운로드했을 때 깨짐 없이 정상 파일로 받아지는 것.
