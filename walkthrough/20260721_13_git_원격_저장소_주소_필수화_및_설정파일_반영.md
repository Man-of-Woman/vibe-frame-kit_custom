## 1. 작업 개요

본 작업은 `vibe-frame-kit`이 Git 원격 저장소 주소 없이도 정상 동작하는지 점검하고, Git 자동화 흐름까지 포함한 실제 사용성 기준에서 문제가 있는지 판단한 뒤, 필요 시 설치 단계와 설정 파일 구조를 함께 보완하기 위해 수행되었습니다.

검토 결과, 기본적인 프레임워크 파일 배포와 개발 흐름 자체는 Git 주소 없이도 동작할 수 있으나, 프레임워크에 이미 탑재된 Git 자동화 의도, 특히 `[git] auto_commit_push = true` 설정과 연계된 작업 완료 후 commit/push 유도 흐름은 원격 저장소 주소가 없으면 완전하게 작동한다고 보기 어렵다는 결론에 도달하였습니다.

이에 따라 설치 시 Git 원격 저장소 주소를 필수 입력값으로 승격하고, 해당 값을 샘플 설정 파일에 자동 반영하도록 구조를 수정하였습니다.

## 2. 주요 변경 사항

### 1) 설치 스크립트에서 Git 원격 저장소 주소를 필수 입력으로 변경

다음 설치 스크립트 2종을 수정하였습니다.

- `install/install.ps1`
- `install/install.sh`

적용 내용은 다음과 같습니다.

- PowerShell 설치 스크립트에 `-GitUrl` 인자를 추가하였습니다.
- Bash 설치 스크립트에 `-g` 인자를 추가하였습니다.
- 인자가 생략된 경우, 대화형 프롬프트로 Git 원격 저장소 주소를 반드시 입력받도록 변경하였습니다.
- 주소 형식 검증을 추가하여 다음 형식만 허용하도록 하였습니다.
  - `https://...`
  - `git@...`
  - `ssh://...`

이를 통해 사용자가 설치 단계에서 Git 원격 저장소 주소를 누락한 채 프레임워크를 적용하는 상황을 차단하였습니다.

### 2) 샘플 설정 파일에 Git 원격 저장소 주소 항목 추가

다음 설정 샘플 파일을 수정하였습니다.

- `common/config/common.config.sample.toml`

`[git]` 섹션에 아래 항목을 추가하였습니다.

```toml
remote_repository_url = "{{GIT_REMOTE_URL}}"
```

이 값은 설치 시 입력받은 Git 주소로 치환되어 최종 샘플 설정 파일에 반영되도록 구성하였습니다.

의미는 다음과 같습니다.

- 작업 대상 프로젝트가 어느 원격 저장소를 기준으로 push 흐름을 가져가야 하는지 명시
- Git 자동화 안내나 검증 기준을 설정 차원에서 명확화
- `auto_commit_push` 설정이 켜진 상태에서 원격 저장소 주소 누락으로 흐름이 붕 뜨는 문제 방지

### 3) 사용자 안내 문서 보완

다음 문서를 함께 수정하였습니다.

- `README.md`
- `common/docs/student-guide.md`

반영 내용은 다음과 같습니다.

- 설치 시 Git 원격 저장소 주소가 필수라는 점을 명시
- 샘플 명령어에 `-GitUrl` 또는 `-g` 인자를 포함
- `config.toml`의 `[git].remote_repository_url` 항목 예시 추가
- 설치 시 입력한 Git 주소가 설정 파일 기본값으로 반영된다는 점을 문서화

이를 통해 실제 사용자 입장에서 설치와 설정의 연결 관계가 문서상으로도 일관되게 보이도록 정리하였습니다.

## 3. 판단 근거

이번 작업에서 핵심 판단은 다음과 같습니다.

- 프레임워크의 “기본 파일 복사”만 기준으로 보면 Git 주소는 없어도 설치 자체는 가능함
- 그러나 이 프레임워크는 단순 템플릿 배포가 아니라, 작업 완료 후 보고서 작성 및 Git commit/push 유도까지 포함한 운영 규칙을 이미 갖고 있음
- 따라서 `[git] auto_commit_push = true` 같은 기능이 활성화될 수 있는 구조라면, Git 원격 저장소 주소는 선택값이 아니라 사실상 필수값으로 다루는 편이 맞음

즉, “부분적으로는 동작”하더라도 “프레임워크 의도 전체 기준으로는 불완전”하므로, 설치 단계에서 선제적으로 보정하는 것이 타당하다고 판단하였습니다.
