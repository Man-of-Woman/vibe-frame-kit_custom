# Codex 오동작 및 깜박임 현상 시스템 상태 점검 보고서

본 보고서는 사용자의 Codex 데스크톱/확장 프로그램이 깜박거리며 오동작하는 문제를 진단하고 원인을 규명하여 해결한 과정을 기록한 문서입니다.

## 1. 점검 및 진단 과정

### ① 프로세스 상태 조회 (`Get-Process`)
시스템에서 실행 중인 프로세스를 조회한 결과, 동일한 `codex.exe` 프로세스가 서로 다른 경로에서 **두 개 이상 실행**되고 있는 상태를 확인했습니다.
* **PID 15288**: Windows 스토어 앱 버전의 `OpenAI.Codex` 데스크톱 프로그램
* **PID 27104**: Antigravity IDE 내부의 `openai.chatgpt` 확장 기능이 구동한 자체 `codex.exe`

### ② 데이터베이스(SQLite) 접근 상태 점검
두 프로세스 모두 사용자 홈 디렉토리인 `C:\Users\mofw7\.codex` 하위의 파일들을 설정 및 데이터 저장소로 사용하고 있었습니다.
* 특히 핵심 로그 파일인 `logs_2.sqlite`의 크기가 **약 135MB**로 비대해진 상태였으며, `logs_2.sqlite-wal` 등 임시 저널 파일에 실시간 쓰기 작업이 반복되고 있었습니다.
* 동일한 데이터베이스 파일에 두 프로세스가 동시에 연결하여 트랜잭션을 처리하는 과정에서 **SQLite 파일 잠금(Lock) 경쟁 및 교착(Deadlock) 지연**이 발생했음을 확인했습니다.

### ③ 네트워크 포트 점유 점검 (`netstat`)
* **PID 27104 (IDE 확장 버전)**: 로컬 포트 `58001`을 점유하고 정상 통신(`ESTABLISHED`) 중이었습니다.
* **PID 15288 (스토어 앱 버전)**: 동일한 포트 `58001`을 바인딩하려 했으나 실패하여, 백그라운드에서 주기적으로 포트 획득을 시도하는 **무한 재시도 루프**에 빠져 있었습니다. 이로 인해 소켓 리소스 낭비 및 CPU 스레드 대기로 인한 화면 깜박임 현상이 심화되었습니다.

## 2. 해결 결과

* **조치 내용**: 포트 바인딩에 실패하고 무한 루프를 돌며 SQLite 파일 락 경쟁을 유발하던 Windows 스토어 앱 버전의 `codex.exe`(PID: 15288)를 강제 종료하였습니다.
  * 실행 명령어: `Stop-Process -Id 15288 -Force`
* **조치 후 상태**: IDE 확장 기능 단일 프로세스(`PID 27104`)만 남겨둔 상태에서 리소스 락이 해제되어 깜박임 현상과 오동작이 멈추고 정상적인 동작 상태로 복구되었습니다.
